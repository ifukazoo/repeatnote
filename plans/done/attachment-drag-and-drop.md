# 添付ファイルのドラッグ&ドロップ対応 計画

ステータス: 完了（実装後レビューの K1・K2 は対応、K3 は見送り）。master へのマージは未実施

## 目的

追加フォームと編集フォームの添付欄（画像・HTML）に、ファイルをドラッグ&ドロップで添付できるようにする。

## 背景

- HTML artifact の計画（`plans/done/html-artifact.md`）では、D&D は「画像に合わせて中止」として見送った
- その後、フォームの添付 UI を `AttachmentField` / `useAttachmentsEditor` に共通化したため、添付欄1か所に D&D を実装すれば、画像・HTML の両方と追加・編集の両フォームに効く

## 確認事項への回答

| No. | 論点 | 決定 |
|-----|------|------|
| 1 | ドロップを受け付ける範囲 | 各添付欄だけ（落とした欄と種類が合わないファイルはエラー） |
| 2 | 対象の種別 | 画像も HTML も |
| 3 | 1つの欄に複数ファイルを同時にドロップ | 全体を拒否し、「1つずつドロップしてください」と知らせる |
| 4 | 添付欄の外へのドロップ | 何も起きないようにする（ページ全体でブラウザの既定の動作を止める） |

## 設計

### 振る舞い

- 添付欄（「📷 画像を追加」「🧩 HTML を添付」のラベルと選択中ファイルの表示を含む枠）にファイルをドラッグしている間は、枠を強調し「ここにドロップ」と表示する
  - 「ここにドロップ」は要素を差し替えず、強調用のクラスと CSS で出す。強調中は枠の子要素に `pointer-events: none` を付ける
  - 出入りは数えて管理し、drop では必ず強調を解除する
  - ファイルのときだけ `preventDefault` ＋ `dropEffect = 'copy'`。ファイル以外（テキストやリンク）のドラッグには反応しない
- ファイル選択とドロップは同じ入口 `selectFiles(kind, files)` を通す（J3）
  - 0個なら何もしない、1つなら `selectFile`、2つ以上ならエラー「ファイルは1つずつ添付してください」で何も選択しない
  - 検証（拡張子・5MB）は既存の `selectFile` のまま。種類が合わなければ既存のエラーメッセージ（例: 「HTML ファイル（.html / .htm）のみ添付できます」）
  - すでに選択中のファイルは置き換える。`selectFile` の成功時に input をリセットする（必須5）
- 編集フォームで「削除」を指示中の種別は、ファイル選択欄を隠しているのでドロップ先も出ない（既存の挙動のまま）
- 「ドラッグ&ドロップ可」の文言は `AttachmentField` の共通部分で1回だけ付け足す（J2）
- ページ全体の処理（`App.tsx`）
  - 添付欄が処理済み（`defaultPrevented`）なら何もしない
  - ファイルのドラッグは `preventDefault` ＋ `dropEffect = 'none'`（無視する）
  - ファイル以外は、落とし先が編集できる要素（textarea / input / contenteditable）なら既定の動作に任せ、それ以外は止める（リンクを落としても画面が移動しない。J1）

### 変更するファイル

| No. | ファイル | 変更内容 |
|-----|----------|----------|
| 1 | `frontend/src/hooks/useAttachmentsEditor.ts` | 入口 `selectFiles(kind, files)` を追加し、`handleFileChange` もこれを使う。`selectFile` の成功時に input をリセット |
| 2 | `frontend/src/components/AttachmentField/AttachmentField.tsx` | 添付欄に `dragenter` / `dragover` / `dragleave` / `drop` を付ける。ラベルに「ドラッグ&ドロップ可」を共通で付け足す |
| 3 | `frontend/src/App.tsx` | ページ全体の `dragover` / `drop` の処理（上記の条件） |
| 4 | `frontend/src/shared.css` | ドラッグ中の枠の強調・「ここにドロップ」・子要素の `pointer-events: none`（デザイントークンを使う。`transition: all` は使わない） |

- サーバー側の変更はない（送信は既存の multipart のまま）
- 新しいフックや部品は作らない。ドラッグ中の状態を使うのは `AttachmentField` の1か所だけのため

## 計画レビューの仕分け

### 必須（計画に取り込み済み）

| No. | 指摘 | 対応 |
|-----|------|------|
| 1 | ページ全体で `dragover` / `drop` を無条件に止めると、textarea・検索欄へのテキストの D&D（移動・挿入）が効かなくなる | ページ全体の処理は「ファイルのドラッグ」のときだけ既定の動作を止める（`dataTransfer.types` に `Files` を含むとき）。テキストは既定の動作に任せる |
| 2 | 出入りの数え方が狂うと強調が残る（drop の後は dragleave が来ない、強調中に子要素が差し替わると leave が足りない、Safari で数が揃わない） | drop で必ず強調を解除する。強調中は枠の子要素に `pointer-events: none` を付けて子要素の出入りを起こさない。「ここにドロップ」は要素を差し替えず CSS で出す |
| 3 | `dropEffect` と実行順が未定義。ページ全体の処理が `dropEffect = 'none'` を無条件に付けると、添付欄へのドロップ自体が起きなくなる | 添付欄はファイルのときだけ `preventDefault` ＋ `dropEffect = 'copy'`。ページ全体の処理は `defaultPrevented`（添付欄が処理済み）なら何もせず、それ以外のファイルは `preventDefault` ＋ `dropEffect = 'none'` |
| 4 | ドロップしたファイルが0個のとき（ページ内の画像のドラッグなど）の動きが未定義 | 0個なら何もしない（強調だけ解除） |
| 5 | ドロップや貼り付けで選び直すと `<input type=file>` の値が古いまま残り、同じファイルをファイル選択で選び直しても change が起きない | `selectFile` の成功時に input をリセットする（原因の1か所で直し、貼り付けにも効く） |
| 6 | テスト計画の不足（jsdom に DataTransfer がない、E2E の書き方、外へのドロップの確認方法） | 下の「テスト計画」に追記 |

### 要判断（J1〜J4 すべて推奨どおり承認済み）

| No. | 指摘 | 対応しない場合の被害 | 対応のコスト | 推奨 |
|-----|------|------|------|------|
| J1 | 必須1で「ファイルのときだけ止める」にすると、リンク（URL）を編集欄以外に落としたときにブラウザがその URL に遷移する | 誤って落としたリンクで、入力途中の本文と添付が消える | ほぼなし（条件を「ファイルなら止める／ファイル以外は、落とし先が編集できる要素なら既定の動作、それ以外は止める」にする） | 対応する |
| J2 | 「ドラッグ&ドロップ可」の文言を種別ごとの文言（`ATTACHMENT_UI` の4か所）に書くか、`AttachmentField` の共通部分に1回だけ書くか。変更後のコードで使う箇所は2つ（画像・HTML） | 種別ごとに書くと、種別を足すたびに書き足しが要り、抜けやずれが出る | ほぼなし | 共通部分に1回だけ書く |
| J3 | `dropFiles` とファイル選択の `handleFileChange` を、「0個なら何もしない／1つなら選択／2つ以上ならエラー」の入口1つ（`selectFiles(kind, files)`）にまとめるか。変更後のコードで使う箇所は2つ（ファイル選択・ドロップ） | 数行の重複が残るだけ | 小 | まとめる |
| J4 | 編集フォームで、現在の添付（サムネイル・「artifact 添付済み」）の上をドロップ先に含めるか | サムネイルに落としても何も起きず、少し迷う | 中（`AttachmentField` の返す要素を包み直し、レイアウトの CSS を調整する） | 対応しない（「📷 画像を変更」の枠の強調で足りる） |

### 見送り

| No. | 指摘 | 見送る理由 |
|-----|------|------|
| 1 | ドラッグ中の状態をフックや部品に切り出す | 使う箇所が `AttachmentField` の1つだけ。2つ目が来てから切り出す |
| 2 | ページ全体の処理を `App.tsx` ではなく `main.tsx` に置く | 置き場所は好みの範囲。ページ全体の問題をルートで防ぐのは妥当 |
| 3 | キーボードでファイル選択を開けない（input が `display: none`） | 既存の問題で、今回の D&D が悪化させるものではない。別タスク |
| 4 | ArtifactModal の iframe の上に落としたファイルが親に届かない | 起きる見込みが薄く、sandbox 側で処理されて親ページの入力は失われない |
| 5 | ドロップが成功しても、前のエラー表示が残る | ファイル選択でも同じ既存の挙動 |
| 6 | 3種類目の添付やフォーム全体のドロップへの備え | 3種類目で D&D 固有の変更は不要。フォーム全体のドロップは要件が来てから |

## テスト計画

- `useAttachmentsEditor.test.ts`: `dropFiles`（1つなら選択される、2つ以上はエラーで何も選択されない、種類違いは既存のエラー、削除指示中の取り消し）
- `AttachmentField` のテスト（新規 `attachment-field.test.tsx`）:
  - ファイルをドラッグすると強調表示、離れると解除、子要素をまたいでも解除されない
  - 画像欄に画像・HTML 欄に HTML をドロップすると選択済みとして表示される
  - 種類違い・複数ファイルのドロップでエラーが出る
  - ファイル以外のドラッグには反応しない
- `app.test.tsx`: 添付欄の外で `drop` / `dragover` の既定の動作が止められる
- E2E: 追加フォームの HTML 欄に HTML をドロップして作成し、artifact を開ける（Playwright で DataTransfer を持つ drop イベントを送る）
  - `page.evaluateHandle` で `new DataTransfer()` に File を入れ、`locator.dispatchEvent('dragenter' / 'dragover' / 'drop', { dataTransfer })` で送る
  - 合成イベントには既定の動作がないため、「外に落としても画面が遷移しない」ことは E2E では確かめられない。`defaultPrevented` を見るユニットテストで代える
- ユニットテストの書き方: jsdom には DataTransfer / DragEvent がないため、`fireEvent.drop(el, { dataTransfer: { types: ['Files'], files: [file] } })` のように渡す。`fireEvent` の戻り値が false なら既定の動作が止められている
- レビューで追加したテスト:
  - textarea へのテキストのドロップを止めない（必須1）
  - 子要素をまたいだ後のドロップで強調が消える（必須2）
  - 添付欄の上では、ページ全体の処理が `dropEffect` を上書きしない（必須3）
  - 0個のドロップでは何もしない（必須4）
  - ドロップで選び直した後に input がリセットされている（必須5）

| No. | 指摘 | 対応しない場合の被害 | 対応のコスト | 推奨 |
|-----|------|------|------|------|
| K1 | 添付欄に透明な 2px の枠線を常に付けているため、ドラッグしていないときも欄が 2px ずつ太り、上の textarea と端がそろわない。ドラッグ中はラベルの破線と外側の破線が二重に見える | 普段の見た目がわずかにずれる（機能への影響なし） | ほぼなし（枠線をやめ、ドラッグ中だけ `outline` で強調する） | 対応する |
| K2 | ラベルの高さが 40px 固定（`height: var(--btn-height)`）で、「・ドラッグ&ドロップ可」を足して文言が長くなったため、狭い画面で折り返すと枠からはみ出す | スマホ幅でラベルの文字が枠からはみ出す | ほぼなし（`height` を `min-height` に変えて折り返せるようにする） | 対応する |
| K3 | ファイルのドラッグかの判定（`types` に `Files` を含むか）が `AttachmentField` と `App` の2か所に重複。共通化すれば使う箇所は2つ | 片方だけ判定を変えると、外へのドロップの扱いが少しずれる | 小（関数を1つ置き、2か所を置き換える） | 対応しない（1行で、App 側は `defaultPrevented` で正しさが保たれている） |

### 見送り

| No. | 指摘 | 見送る理由 |
|-----|------|------|
| 1 | 外から使われていない `selectFile` がフックの戻り値で公開されたまま | 現状の被害はなく、master から公開されている |
| 2 | 検証エラーのときは input をリセットしないため、同じ不正なファイルを続けて選ぶと2回目にエラーが出ない | 既存の挙動で、今回悪化していない |
| 3 | checkbox などの input にリンクを落とすと画面が移動しうる | アプリ内の input は検索欄と隠したファイル選択欄だけで、起きる経路がない |
| 4 | 強調が残ったままになると、子要素を押せなくなる | 残る経路を確認できず、もう一度ドラッグで出入りすれば戻る |
| 5 | 編集フォーム（mode="edit"）でのドロップのユニットテストがない | 処理は追加フォームと同じ部品・同じフックを通る |
