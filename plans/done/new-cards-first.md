# 未復習カードを表示順の先頭にする

## 要望

登録したばかりのカードは記憶が薄いうちに一度復習したい。一度も復習していないカード（`review_count === 0`）を、期限を過ぎたカードより先に表示する。

## 採用案（案A）

- `review_count === 0` のカードを先頭にする。その中は `created_at` の昇順（登録の古い順）。
- それ以外は従来どおり `next_review` の昇順（null は先頭）。
- ソート関数を純粋関数として別ファイルに切り出し、テストは本物を import する（現状のテストはロジックを書き写しており、本物を検証していない）。

## 不採用案

- 比較関数だけ直してテストはそのまま: 現行テストは実装と無関係に通るため、変更が検証されない。

## 決定事項・推奨デフォルト

1. 未復習どうしは登録の古い順（ユーザー決定）。
2. 「すべて表示」でも同じ並び順（推奨デフォルト。ソートは1つ）。
3. マスター済みかどうかは並び順に影響させない（デフォルト表示ではマスター済みは除外されるため実害なし）。
4. `review_count` は低評価でもリセットされないので、0 は「一度も復習していない」と同じ意味（`server/src/sm2.ts`）。
5. `review_count` と `created_at` は常に正しい値が入っている前提とする（手で編集して欠けたノートは並び位置が崩れるだけで、データは失われない）。

## 変化の方向

- 並び順のユーザー切り替え: 見込み低（ユーザー回答）→ 拡張点は作らない。

## 不可逆な決定

なし（フロントエンドの表示順のみ。保存データ・API・サーバーは変更しない）。

## 設計

- ドメインロジック（並び順）は `sortItems.ts` の純粋関数。入力は `Item[]`、I/O なし。
- `ItemList.tsx` は呼び出すだけ。

## テスト計画（`sorting.test.ts`）

テスト内に `makeItem(overrides)` ファクトリを置き、各アイテムに id を付けて id の並びで検証する。

既存（本物の関数で書き直す）:
- next_review が null の項目が復習済みの中で先頭
- 次回復習日の昇順
- 複数の null
- 元の配列を変更しない
- 空配列
- 同一日時の安定ソート（id で入力順が保たれることを確認）

追加:
- 復習回数 0 のカードが、next_review が過去のカードより先頭に来る
- 復習回数 0 どうしは created_at の昇順（next_review の順と逆になる入力で確認）
- 復習回数 0 と、復習済みで next_review が null のカードでは、復習回数 0 が先
- 復習回数 1 以上は 0 扱いされない（境界値: 0 と 1）
- 復習回数 0 で created_at も同じなら入力順が保たれる
